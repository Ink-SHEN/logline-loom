# 决策记录：创空间部署（2026-09-08）

**背景**：Agent 赛道要求「电影 Agent 部署至魔搭创空间」，提交截止 09-14 22:00。
`space/README.md` 里卡了三天的 A/B 方案问题今天必须拍板，否则来不及写代码和联调。

**决定（A/B/C 三案的处置）**：按 **A 做，把 B 做成兜底**，同一份代码里的一个开关；**C 不做**。

| 项 | 决定 | 依据 |
|---|---|---|
| 创空间 SDK 类型 | **gradio** | 界面就是「输入 logline → 展示契约产物」，Gradio 够用且启动最快；docker 需阿里云绑定+实名认证，时间不划算 |
| 入口文件位置 | 仓库根目录 `app.py` | 创空间要求入口在根目录；`space/` 退化为 python 包，只放逻辑 |
| Agent 人格 | 运行时解析 `agents/*/prompt.js` | 不复制一份，避免「改了 Agent 脾气、创空间还是旧的」 |
| 契约校验 | 复用 `contracts/validate_contract.py` | 创空间里跑的校验与本地命令行同一份代码，评审看到的结果可复现 |
| 回放素材 | 6 段已生成镜头入库（`space/fallback/`，`.gitignore` 开白名单） | 评审期隧道不可达时的兜底；仓库只多 9 MB |
| 人工关口 | 默认自动批准（演示模式）并在界面 ⚠️ 标注；取消勾选则真的阻塞 | 既保证「一句 logline 全自动跑通」拿自动化分，又保留机器拦的合规证据 |
| 真生成后端 | `LOOM_COMFY_URL` + `LOOM_PROXY_TOKEN`，探测可达才 POST | ComfyUI 无鉴权，绝不裸奔公网；只在评审期开隧道 |

**为什么 C（创空间自己租 GPU 拉权重）不做**：63 GB 且是 ARM64 专用的 int8 量化权重，
x86 GPU 上未必跑得起来，10 天内风险最大。

**为什么 B 的掉分比直觉小**：评分里真正与「现场是否真跑」强绑定的只有自动化 4% 与稳定性 3%，
架构那 30 分靠的是 Agent 分工、调度与上下文管理、反馈闭环与可观测性、云端本地协同、合规机制
——这些在 B 方案下依然全部成立，因为**编排逻辑是真的在跑**，只是视频后端换成了预生成结果。

**未决**：隧道地址与 token 由 C 提供后配置到创空间 secrets；评审期隧道的开启/关闭流程待补。

LOOM 电影 Agent · 本地使用指南

在自己电脑上，把一句话跑成一部片

这份指南面向「clone 了 LOOM 仓库、想在本地把它跑起来」的人。全程大白话：哪条命令敲下去会发生什么、屏幕上会打出什么、什么时候轮到你出手。不烧一卡一瓦的部分先彩排，烧 GPU 的部分最后再上。

$ node studio.mjs --logline "你的故事，20–400 字"
1

先看全景：这条流水线长什么样

把 LOOM 想成一条小工厂流水线：7 个「工人」（Agent）排成一排，每人只干自己的那道工序，干完把半成品（一份 JSON 交接单）传给下一位。流水线上有 2 道只有你能签的「放行闸」——机器不会替你签字，你没签字流水线就停在那等你。

图 1 · LOOM 流水线全景：实线是正常流向，虚线红字是「不合格打回重做」的回环

你真正要做的事只有四种：

  1. 写一句话故事（起点，也是天花板——写得越具体，后面越像那么回事）
  2. 在两道关口上签字（剧本好不好、粗剪行不行，机器不替你判断）
  3. 照着屏幕提示敲续跑命令（每站跑完都会把下一条命令打印出来）
  4. 等着收成片
2

跑之前：装什么、哪台机器干什么活

2.1 你的电脑上要装的东西

想干什么需要装什么
把仓库 clone 下来先验个货Python 3（装完执行 pip install jsonschema），然后跑一次 python contracts/validate_contract.py --selftest，看到 7 份示例全 [通过] 就说明仓库完好
跑流水线（必装）Node.js 18 或更新（命令行敲 node -v 能出版本号就行）。LOOM 的代码零第三方依赖，不用 npm install
让 ①②③⑦ 真的动脑子写东西（可选）一个大模型 API Key。默认用魔搭 API-Inference：export MODELSCOPE_API_KEY="ms-xxxx"（Git Bash 写法）。也认 DASHSCOPE_API_KEY / OPENAI_API_KEY，可用 LOOM_LLM_MODEL 换模型。不配也行——加 --offline 会用内置示例顶上
渲染成片 MP4（可选）ffmpeg（要带 libass；烧中文字幕需要渲染机装中文字体，否则字幕变方块）。Windows 可 winget install ffmpeg
真生成视频（可选，最重的一步）一台跑着 ComfyUI 0.34.0 + MiniMax-H3 权重（约 63 GB）的机器（README 第四节有完整清单）。没有它，流水线照样能跑到「生成提交计划」为止

2.2 活都发生在哪台机器上

图 2 · 平时只占用你的笔记本；只有第 ④ 步才需要生成机在线
💡
没有 Spark 也能玩。流水线的每一站都可以单独跑、单独看产物。先彩排（下一节），把剧本、分镜、提示词这些「不花钱的部分」跑顺，最后再决定要不要上真生成。
3

三种跑法：先彩排，再开演

同样是 node studio.mjs …，加两个开关就是完全不同的「火力档位」：

--offline

彩排模式

不调大模型：剧本、分镜用内置示例顶上，管线照走、产物照存。用来熟悉流程、检查环境，产物是「占位样品」不是创作。

--dry-run

后厨看单模式

提示词是真的，但第 ④ 步只打印「我打算提交什么」的清单，不真的发给 GPU。上真生成前用它过目一遍点菜单。

都不加

正片模式

大模型真写、GPU 真渲染、质检真判、不合格真打回重做。烧时间也烧电，建议小样先跑。

✅
两个开关都不烧 GPU、不要 API Key，可以随便组合：--offline 管的是 ①②③⑤⑦ 用不用大模型，--dry-run 管的是 ④ 发不发 GPU。
4

三分钟彩排：不烧 GPU、不要 API Key，跑通全流程

打开终端（Windows 建议 Git Bash），进到仓库目录，照抄三步。跑完你对整条流水线就心里有数了。

起步：交一句话故事
终端 1node studio.mjs --logline "一位独自值守射电望远镜的夜班技师，在最后一个班次收到一段来自自己未来的信号。" --offline

它会跑完 ①编剧，然后把剧本存到 artifacts/screenplay_时间戳.json，紧接着停下一块写着「强制人工关口 1」的大牌子，并把批准命令原样打印给你。这不是卡住了，是设计如此。

──────────────────────────────
 强制人工关口 1：剧本确认（c02）
 剧本：artifacts/screenplay_20260909xxxxxx.json

 1. 读剧本 → 2. 满意就批准（只有人能批）：
    node studio.mjs --approve artifacts/screenplay_20260909xxxxxx.json --reviewer 你的名字
 3. 批准后从 ② 续跑：
    node studio.mjs --from 2
──────────────────────────────
签第一道关口：读剧本，批或不批

先用编辑器打开 artifacts/screenplay_时间戳.json 看一眼（彩排模式下是一份示例剧本，正片模式下是大模型写的）。满意就照抄刚才打印的命令：

终端 2node studio.mjs --approve artifacts/screenplay_20260909xxxxxx.json --reviewer 你的名字

你的名字会被永久写进这份文件的 gate.reviewer 字段——谁批的，账上永远查得到。批准后它会立刻再跑一遍契约校验，看到 [通过] 才算数。不批就回去改剧本重新来，别手工改 JSON 里的状态——机器只认 --approve 这条通道。

续跑：一路冲到「生成提交计划」为止
终端 1node studio.mjs --from 2 --offline --dry-run

--from 2 = 从第 ② 站接着跑；--dry-run = 第 ④ 站只出「提交计划」不碰 GPU。你会看到 ②分镜 → ③提示词 一站站过，最后打出「离线自检到此为止」——这就是不花一分钱的整线自检终点。此时 artifacts/ 里已经有片约、剧本、分镜、提示词四样产物了。

[编排] ② 完成：artifacts/shotlist_20260909xxxxxx.json（离线示例降级）
[编排] ③ 完成：artifacts/genreq_20260909xxxxxx/（6 份 c04）
[编排] ④生成 是 --dry-run（只出提交计划，未 POST、未落 c05）——没有产物可质检，离线边界到此为止。
💡
每条命令跑完，终端都会打印下一站的完整命令（连着真实的文件路径），照抄就行，不需要记任何路径规则。
5

真出片：完整旅程（含两道关口）

下面是「从一句话到成片 MP4」的完整 7 步。带 🔥 的步骤会烧 GPU 或调大模型，其他步骤都是本地秒级操作。

写一句好故事，正式起步
第 1 步node studio.mjs --logline "你的故事" --duration 90 --candidates 2

第一次真跑建议像上面这样把片子做小：--duration 90（秒，60–300）+ --candidates 2（每镜候选数，默认 3）。镜头少一半，时间和电费也少一半。可选输入还有 --theme（主题）、--visual-style（视觉风格）、--audio-style（声音风格）、--character（主角设定）、--red-lines（红线，绝对不能出现的内容）。没配 API Key 就加 --offline。

关口 1：读剧本 → 批准
第 2 步node studio.mjs --approve artifacts/screenplay_时间戳.json --reviewer 你的名字

这一步是全片质量的根。剧本不行，后面全是废片——在这里多磨 10 分钟，能省 GPU 上几个小时。

跑分镜和提示词（不烧 GPU，先看看要生成什么）
第 3 步node studio.mjs --from 2 --until 3

--until 3 = 跑到第 ③ 站就停。这一步过后，artifacts/genreq_时间戳/ 里躺着每个镜头每个候选的一份生成指令。想再稳一点，可以先看看点菜单：

可选node studio.mjs --from 4 --genreq artifacts/genreq_时间戳/ --dry-run
接通生成机（有 Spark / 远程 GPU 的人才需要）
第 4 步ssh -L 8188:127.0.0.1:8188 你的生成机

开一条 SSH 隧道，让本机的 127.0.0.1:8188 通到生成机上的 ComfyUI。ComfyUI 完全没有密码，所以永远走隧道、地址不写进任何文件。如果生成机就在本机，这步跳过。

真生成：④⑤⑥ 自动回环，你去干别的
第 5 步 🔥node studio.mjs --from 4 --genreq artifacts/genreq_时间戳/

接下来是全自动的：④提交 → ⑤质检 → 不合格的 ⑥换个种子打回 ④ 重来，最多 3 轮（--max-retries 可调）。每隔一会儿终端会打一行战报：

[编排] ——— 回环第 2 轮（重试批）：artifacts/genreq_retry_..._r1 ———
[编排] ⑤ 质检：pass 5 · retry 1 · human 0（累积 artifacts/qc_20260909xxxxxx）

质检分两层：硬指标（时长/帧率/分辨率/有没有音轨）用 ffprobe 机器量，模型一个字不参与；内容项（画面有没有走样、有没有碰红线）由视觉模型或人复核。谁都不许把「没看过」伪装成「合格」——这是这条流水线的底线。

⑦ 剪辑出决策单 + 自动渲一版审阅粗剪

回环收敛后 ⑦ 自动接手：从合格的候选里挑片、排顺序、定转场、配字幕，产出剪辑决策单 artifacts/edit_时间戳.json，并当场渲染一版「审阅粗剪」MP4 给你过目（需要 ffmpeg）。然后停在关口 2：

──────────────────────────────
 强制人工关口 2：粗剪确认（c07）
 审阅粗剪：deliverables/final_20260909xxxxxx.mp4

 1. 全组看过粗剪 → 2. 满意就批准（只有人能批）：
    node studio.mjs --approve artifacts/edit_20260909xxxxxx.json --reviewer 你的名字
 3. 批准后交付成片（不会再烧一遍）：
    node studio.mjs --from render --edit artifacts/edit_20260909xxxxxx.json
──────────────────────────────

把粗剪拖进播放器看。不满意就按屏幕提示把意见回给上游（换候选/改字幕），别直接手改决策单。

关口 2：签字 → 交付
第 6 步node studio.mjs --approve artifacts/edit_时间戳.json --reviewer 你的名字 --reason "节奏可以，交付"
第 7 步node studio.mjs --from render --edit artifacts/edit_时间戳.json

因为审阅粗剪在关口 2 之前就已经渲染并回填完毕，最后这一步只做核验、不再重烧，几秒钟收工。成片在 deliverables/final_时间戳.mp4——带字幕、混音和「AI 生成」标识（主赛道硬要求，跳不过去）。

整个流程的命令清单（收藏用）

# ① 起步（到关口 1 停）
node studio.mjs --logline "你的故事" --duration 90 --candidates 2
# ★ 关口 1：读 artifacts/screenplay_*.json，批：
node studio.mjs --approve artifacts/screenplay_时间戳.json --reviewer 你的名字
# ②③ 分镜+提示词（不烧 GPU）
node studio.mjs --from 2 --until 3
# （可选）过目生成计划
node studio.mjs --from 4 --genreq artifacts/genreq_时间戳/ --dry-run
# 🔥 ④⑤⑥ 真生成 + 质检回环 → ⑦ 剪辑 → 渲染审阅粗剪（到关口 2 停）
node studio.mjs --from 4 --genreq artifacts/genreq_时间戳/
# ★ 关口 2：看 deliverables/final_*.mp4，批：
node studio.mjs --approve artifacts/edit_时间戳.json --reviewer 你的名字
# 交付核验（秒级）
node studio.mjs --from render --edit artifacts/edit_时间戳.json
6

要等多久：把预期先说明白

写剧本的几秒到几分钟，看片头的「冷启动」十分钟起步——大部分等待都在 GPU 生成上，而且是正常的。下面是实测基线（README 第六节，848×480 档位）：

LLM 工位（①②③⑦ 各一次）
数秒～2 分钟
生成首次冷启动（含载 63GB 权重）
≈ 10.6 分钟
热态 I2V 一个 5 秒镜头
≈ 3.6 分钟
热态 I2V 一个 4 秒镜头
≈ 2.1 分钟
输入完全相同（命中缓存）
0～1.4 秒

粗算一下：90 秒小样约 8–10 个镜头 × 2 候选 × 热态 2–4 分钟/个 ≈ 1–1.5 小时 GPU 时间；首次还要加上 10 分钟冷启动。挂后台跑，人不用守着。

  • 为什么同一个镜头出多个候选必须换种子？ComfyUI 会缓存完全相同的输入，0 秒把旧视频还给你。⑥重试 的主要工作就是换种子。
  • 为什么 T2V/I2V/R2V 要分批跑？三种工作流用不同权重（21 GB+），来回切换就得反复重载。②分镜 出的 batch_plan 就是干这个的。
  • 防烧穿保险丝：--max-retries（默认 3）限制了回环轮数，质检判「重试次数耗尽」会转人工，绝不无限烧 GPU。

东西都存哪了（以及一个 git 陷阱）

LOOM/ ├─ artifacts/ ← 全部中间产物（JSON 契约），文件名自带时间戳 │ ├─ brief_时间戳.json 你写的一句话故事（c01） │ ├─ screenplay_时间戳.json 剧本（c02）★ 要你点批 │ ├─ shotlist_时间戳.json 分镜表（c03） │ ├─ genreq_时间戳/ 生成指令，每候选一份（c04） │ ├─ genreq_retry_…_r2/ ⑥重试 产出的新指令批 │ ├─ qc_时间戳/ 质检报告（c06） │ └─ edit_时间戳.json 剪辑决策单（c07）★ 要你点批 ├─ shots/ 生成出来的镜头视频 + 参数快照 + 哈希（视频本身不入库） ├─ deliverables/ 成片 final_时间戳.mp4 └─ tmp/ 渲染中间文件，成功自动清
⚠️
git 陷阱：artifacts/ 没有进 .gitignore。试跑产生的中间产物不要 git add -A 一把梭提交进仓库。提交前先 git status 看清楚，只 add 你真的改的源码文件。
💡
这套目录就是「可追溯」的兑现：成片里任何一个镜头，都能顺着 qc 报告 → 生成指令 → 分镜 → 剧本 一路反查回你最初那句话，连当时用的随机种子都记着。

常用参数速查（studio.mjs）

权威清单永远是 node studio.mjs --help。这里只挑常用的：

参数干什么用
--logline "…"一句话故事，唯一必填，20–400 字
--duration 90目标片长（秒），只认 60–300
--candidates 2每镜头出几个候选（1–8，默认 3）。直接决定 GPU 时长，小样建议 2
--offlineLLM 工位不调模型，用内置示例顶上
--dry-run④ 只出提交计划，不 POST 不烧 GPU
--from 2 / --until 3从哪站续跑 / 跑到哪站停（1 编剧 → 2 分镜 → 3 提示词 → 4 生成回环 → 5 剪辑 → 6 渲染，名字数字通用，render 也认）
--approve 文件 --reviewer 名字人工关口点批专用（只有人能跑），可加 --reason "一句话理由"
--genreq 目录从 ④ 续跑时指定生成指令批次（--from 4 必给）
--max-retries 3回环重试上限，防无限烧 GPU
--model 名称本次换用别的 LLM（平时用环境变量 LOOM_LLM_MODEL 更省事）
--endpoint 地址ComfyUI 地址（默认 http://127.0.0.1:8188，或环境变量 LOOM_COMFY_URL）
--vision⑤ 质检开启抽帧视觉复核（需 ffmpeg + 视觉模型 Key）

出问题怎么办：先对号入座

大部分「问题」其实是设计。对照下表：

现象怎么回事 / 怎么办
终端打出「强制人工关口…停下等人」不是故障。流水线在等你签字。照屏幕上打印的 --approve 命令执行，再按提示续跑。
未配置 API Key配 MODELSCOPE_API_KEY（或 DashScope/OpenAI 任一），或者干脆加 --offline 彩排。
② 缺上游 c02 / 回环缺起点批次续跑时没找到上一步的产物。要么从更前面的站重跑，要么用 --screenplay / --genreq 明确给路径。
校验打出 [不通过] … 'envelope' is a required property产物 JSON 缺外壳。报错会逐条写缺哪个字段，照着补。你手工编辑过产物文件？别手改，回上游 Agent 重跑。
批准命令报「不是可批的关口产物」--approve 只吃两种文件：剧本（c02）和剪辑决策单（c07）。别的文件不用批。
回环结束后「没有一条 pass」机器不敢往下走是刻意的。看终端列出的「需要人工处理的项」和 artifacts/qc_…/ 里的报告，处理完用 --from 4 --genreq … --qc-dir … 续跑。
渲染时说没有 ffmpeg / 字幕变方块装 ffmpeg（含 libass）和中文字体后重跑 --from render。没有 ffmpeg 时流水线会跳过审阅粗剪渲染、按决策单审，不阻塞。
生成很慢 / 卡住不动先想「冷启动 10 分钟、热态单镜 2–4 分钟」是不是还没到。再查 ComfyUI 页面（127.0.0.1:8188）看队列。
Value not in list: image参考图素材没先上传到 ComfyUI。用 ③ 的素材清单（--assets）+ ④ 的自动上传通道，别手工裸 POST。
命令退出码 1 或 2全仓库统一口径：0 正常（含关口停靠）、1 运行出错、2 命令用法不对（参数拼错等）。
在别的目录跑报 SyntaxError: Unexpected token 'export'那个目录缺 package.json。补一份 {"type":"module"} 即可（本仓库自带）。
💡
更深的坑（节点 ID、权重摆放、ComfyUI 升级后重校验等）看两份文档：README.md 第七节「已知限制」和 docs/agent_guide.md 第九节「症状→原因→修法」。

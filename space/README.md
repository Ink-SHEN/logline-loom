魔搭创空间部署。**Agent 赛道（进阶创作｜电影 Agent）的提交项。**

## 一、要解决的核心矛盾

创空间跑在魔搭的云上。那里**没有我们的 DGX Spark，也没有那 63 GB 权重**。
而评审项里有一道「统一一句话生成测试」（25 分）——
评委给一句 logline，要求现场看到 Agent 跑出东西来。

这两件事直接冲突。所以创空间里的「生成」到底怎么发生，必须先定。

---

## 二、三个方案

| 方案 | 做法 | 代价 | 判断 |
|---|---|---|---|
| **A** | 创空间当薄前端，HTTP 回调 Spark 上的 ComfyUI | ComfyUI **完全没有鉴权**，必须套一层带 token 的反向代理，且只在评审期开放 | 真生成，最加分 |
| **B** | 创空间只跑 Agent 编排 + 展示预生成结果 | 「一句话生成」实际是回放的 | 最稳，掉分不多 |
| **C** | 创空间自己租 GPU 拉权重 | 63 GB 且是 **ARM64 专用的 int8 量化权重**，x86 GPU 上未必跑得起来 | 10 天内风险最大，**不建议** |

### 为什么 B 的掉分比直觉小

按评分细则，Agent 赛道的分值分布是：

| 项 | 分值 |
|---|---|
| 多 Agent Harness 架构与工程实现 | **30** |
| 统一一句话生成测试 | 25 |
| 技术创新与模型工程 | 25 |
| 自主作品质量 | 10 |
| 复现开源与部署能力 | 10 |
| └ 其中：自动化程度 | **4%** |
| └ 其中：稳定性 / 完成率 | **3%** |

真正跟「现场是不是真跑了」强绑定的只有自动化程度 4% 与稳定性 3%。
架构那 30 分靠的是 Agent 分工、调度与上下文管理、反馈闭环与可观测性、
云端本地协同、合规机制——**这些在 B 方案下依然全都成立**，
因为编排逻辑是真的在跑，只是视频后端换成了预生成结果。

### 建议：按 A 做，把 B 做成兜底

不是二选一，是**同一份代码里的一个开关**：

```
创空间收到 logline
      │
      ▼
  Agent 编排（编剧→分镜→提示词）      ← 这一段两个方案完全一样，都是真跑
      │
      ▼
  探测 Spark 隧道是否可达（带超时，比如 5 秒）
      │
   ┌──┴───────────────┐
 可达                不可达
   │                   │
   ▼                   ▼
POST /prompt      播放预生成结果
真生成            并在界面上【明确标注】
                  「本次为预生成回放」
```

关键是**标注**。评审当天网络出问题，界面自己说清楚是回放，
比悄悄放一个旧视频要安全得多——后者一旦被看出来是造假，
丢的就不只是那 7% 了。

### 如果选 A，安全上有三条不能让步

1. **ComfyUI 绝不能直接暴露公网。** 它没有任何鉴权，
   暴露出去等于任何人都能 `POST /prompt` 烧我们的 GPU，
   也能 `GET /history` 读走全部产物
2. **代理层必须校验 token**，且 token 走环境变量，
   **不进仓库**（`.gitignore` 已排除 `.env`、`*.token`、`config.local.*`）
3. **只在评审期开放。** 评审结束后立刻关掉隧道，
   节点回到 `--listen 127.0.0.1` 只监听回环的状态

## 四、定了之后这个目录应该长什么样

```
space/
  app.py                 Gradio 界面：输入 logline → 展示 7 个 Agent 的中间产物
  requirements.txt       创空间侧依赖（不含 ComfyUI，它跑在节点上）
  proxy/                 方案 A 才需要：带 token 的反向代理
  fallback/              方案 B 的预生成结果索引（媒体文件本身不入库）
  README.md              部署步骤 + 环境变量清单
```

界面设计上有一件事值得强调：**把 7 个 Agent 的中间产物都显示出来**，
而不是只显示最终视频。契约 JSON 本身就是给人看的，
评委能看到 c01 → c07 一路传下来的结构化数据，
这比一段视频更能证明「多 Agent Harness」是真的存在。
